# csub 能力边界

> **依据：42 份真实学生代码的实测 + 可复跑的能力探针。**
> 每个数字都能用 `python tools/probe_limits.py` 复现。
>
> 最后更新：2026-10-22（v1.0）

## 一、结论

| 维度 | 现状 |
|---|---|
| 诊断规则 | **39 条**（13 错误 + 26 警告） |

## 二、前端能解析什么（18/19）

实测项：`python tools/probe_limits.py` 的第 [1] 张表。

### 支持

| 语法 | 备注 |
|---|---|
| 基本语法（变量/条件/循环/函数） | |
| `struct` / `typedef` / `enum` / `union` | 含匿名声明的成员提升 |
| 位字段 `unsigned a : 1` | 只解析，不做内存布局 |
| 匿名 `struct` / `union` 嵌套 | |
| 函数指针（成员、变量、数组、参数、返回值） | 回调表都能解析 |
| 复合字面量 `(P){1,2}` | C99 |
| 指定初始化器 `{[0]=1, [2]=3}`、`{.a=1}` | C99 |
| VLA 变长数组 `int a[n]` | |
| `goto` / `label:` | |
| `_Bool` / `bool` / `true` / `false` | |
| `restrict` / `volatile` / `const` / `inline` | |
| `__attribute__((...))` | 语法跳过，不生效 |
| 头文件保护 `#ifndef H / #define H / #endif` | |
| 函数式宏（含 `#x` 字符串化、`a##b` 拼接） | |
| `va_list` / `va_start` / `va_arg` / `va_end` | |
| 预定义宏 `__func__` / `__FILE__` / `__LINE__` | 值按占位处理 |

### 不支持

| 语法 | 表现 |
|---|---|
| **宽字符字符串/常量** `L"中文"` / `L'A'` | 解析失败 |

## 三、后端能编译什么（12/17）

实测项：`python tools/probe_limits.py` 的第 [2] 张表。

### 支持（生成 x86-64 汇编 → 链接 → 运行）

| 特性 | |
|---|---|
| 算术 / 逻辑 / 位运算 | |
| `if` / `while` / `for` / `switch` / `do-while` | |
| 函数调用（含 5+ 参数栈传参） | |
| 递归 | |
| 一维数组（局部） | 含越界检查 |
| 指针算术（含 `char*` 步长） | |
| `char*` 解引用 | |
| `float` / `double` | |
| 全局变量 | |
| `malloc` / `calloc` / `free` | |
| 字符串函数（`strlen` / `strcpy` / `strcmp`） | |
| `printf` / `puts` / `putchar` | |

### 不支持（会明确报错，不静默算错）

| 特性 | 报错信息 |
|---|---|
| **数组作函数参数** `int sum(int a[], int n)` | "数组参数退化为指针的语义未实现" |
| **函数内定义结构体**（`struct P {...} p;`） | "没有 main 函数"（连带） |
| **全局数组** `int g[4];` | "全局数组带布局的后端尚未支持" |
| **多维数组** `int a[2][3]` | 不支持 |
| **函数返回结构体** | 不支持 |

> 这些限制**只影响 `tools/codegen.py` 真正编译执行**。
> `csub.py check`（查错）对这些写法**完全正常**——
> 查错用的是前端，与后端能力无关。

## 六、查不出来的（结构上做不到）

五类，**不是 bug**。详见 [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md)。

### 1. 算法/数学逻辑错误

```c
// 完美数：只加小因子，漏了配对的 num/i
if (num % i == 0) { ans += i; }     // 该同时加 num/i
```

语法、类型、控制流全对，错在没理解数学事实。

### 2. 内存泄漏 / 资源泄漏

```c
int* ans = malloc(n * sizeof(int));
if (k == 0) { return; }             // 提前返回，ans 没 free
```

需要路径分析 + 别名分析。

### 3. 跨行语义不一致

```c
while (x != 0) {
    int y = x % m;      // 按 m 进制取位
    x /= 10;            // 却按 10 进制右移
}
```

每行单独都合法，错在两行意图不一致。

### 4. 运行时越界（长度来自输入）

```c
bool f(int* nums, int numsSize) {
    if (numsSize < 3) { if (nums[1] > nums[0]) ... }  // numsSize==1 时越界
}
```

`nums` 是参数，长度未知；条件运行时才定。

### 5. 算法复杂度

需要跨函数分析循环嵌套深度。

## 七、csub vs gcc

| 维度 | gcc | csub |
|---|---|---|
| 语法错误 | ✅ 完整 + 错误恢复 | ⚠️ 子集，有单层恢复 |
| 类型检查 | ✅ 完整 | ⚠️ 简化模型 |
| 未初始化 | 需 -Wall | ✅ 默认开 |
| 数组越界（常量） | 需 -Warray-bounds | ✅ 默认开 |
| 数组越界（循环变量） | ❌ | ✅ W16（有限场景） |
| 整数溢出 | ✅ -Woverflow | ✅ W14 |
| 死循环 | ❌ | ✅ W15/W18 |
| 栈溢出风险 | ❌ | ✅ W19 |
| malloc 分配不足 | ❌ | ✅ W29 |
| 漏 include | ✅ error | ✅ W25 |
| 内存泄漏 | ❌（需 -fanalyzer） | ❌ |
| 算法复杂度 | ❌ | ❌ |
| **中文诊断** | ❌ | ✅ |

**真正的差异在「能编译但会出事」这一层**——
W13/W15/W16/W18/W19/W29 是 gcc 不做的。
