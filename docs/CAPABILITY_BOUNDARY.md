# csub 能力边界

> 这份文档回答一个问题：**csub 能查什么，不能查什么，什么情况下会误报。**
>
> 依据是 11 份真实学生代码（`examples/student_real/`）的实测，
> 不是自评。每一条边界后面都标了是哪个样本撞出来的。

---

## 一、先说结论

| 维度 | 现状 |
|---|---|
| 规则总数 | 30 条（13 错误 + 17 警告） |
| 真实学生代码崩溃 | 0（11 份全部跑通） |
| 真实学生代码误报 | 0（修完 E16 之后） |
| 真实学生代码真检出 | 6/11 |
| 明确的能力盲区 | 4 类，见第四节 |

**最重要的一条**：csub 的定位是「拦下能编译但会出事的代码」，
不是「替代 gcc」。gcc 报的它大多也报，gcc 不报的一部分它能报，
但**算法层面的错误它基本查不出来**。

## 二、能查什么（按可信度排序）

### 高可信 — 几乎不会误报

| 码 | 查什么 | 验证样本 |
|---|---|---|
| E1 | 使用未声明变量 | 多份 |
| E2 | 使用未初始化变量 | stu_01 |
| E3 | 重复声明 | — |
| E4/E14 | 函数参数个数不对 | — |
| E5 | 调用未声明函数 | — |
| E12 | 除数是常量 0 | — |
| E13 | 常量下标越界 | — |
| E15 | 结构体没有该成员 | — |
| E18 | 给数组整体赋值 | — |
| E17 | 表达式嵌套过深（健壮性保护，不是代码错误） | fuzz |
| W6 | 变量声明后从未使用 | — |
| W19 | 局部大数组爆栈（>256KB） | **stu_09** |

### 中可信 — 有明确豁免规则，边界清楚

| 码 | 查什么 | 豁免条件 |
|---|---|---|
| E16 | scanf 漏写 `&` | **数组名/指针变量不报**（stu_11 撞出的误报） |
| W2 | 有符号/无符号混合比较 | 常量、指针比较不报；`strlen` 按 size_t 处理（stu_05） |
| W3 | 整数除法丢精度 | **分子是变量时不报**（`n/2` 是算法惯用法，stu_02）；只报字面量相除 |
| W5 | `if (a = 1)` 赋值当比较 | — |
| W8 | 非 void 函数缺 return | if 链有无 else 兜底；有 return 就放行 |
| W9 | 返回局部变量地址 | 全局/static/形参/malloc 不报 |
| W11 | 指针与整数隐式转换 | 空指针常量、显式转换不报 |
| W13 | `if (cond);` 空分支 | **条件含函数调用不报**（`while(getchar())` 惯用法） |
| W17 | 没有 main | 只是提示级，不阻塞其他诊断（stu_02） |

### 低可信 — 只在形状非常明确时才报

| 码 | 查什么 | 限制 |
|---|---|---|
| W10 | 数组传给非数组形参 | 只看直接传数组名 |
| W12 | char 赋超范围值 | 只看字面量常量 |
| W14 | 常量表达式溢出 int | **long/unsigned 一律不报**（回绕是定义行为） |
| W15 | 循环死循环 | 只在「变量 vs 常量」比较中收集；有 break/return/函数调用不报 |
| W16 | 循环下标越界（off-by-one） | 只支持 for 标准形态 + 常量边界；`n` 来自输入时不报 |
| W18 | 递归到不了基线 | 只认 `n ± 常量` 直接形态，嵌在表达式里解析不出 |
| W4 | float 赋给 int | — |

## 四、明确查不出来的（能力盲区）

这四类**不是 bug，是结构上做不到**。使用者应该知道。

### 1. 内存泄漏 / 资源泄漏

```c
int* ans = malloc(n * sizeof(int));
if (k == 0) { return; }        // ← 提前返回，ans 没 free
free(ans);
```

**样本：stu_06**

为什么不查：需要路径分析（哪些 return 路径没走到 free）+ 别名分析
（`ans` 是否被转移到别处）。真实代码里提前 return 到处都是，
误报风险远超收益。

### 2. 跨行语义不一致

```c
while (x != 0) {
    int y = x % m;      // 按 m 进制取位
    x /= 10;            // ← 却按 10 进制右移
}
```

**样本：stu_07**

为什么不查：每一行单独都合法，错误在于两行之间的**意图不一致**。
同样的代码形状有对有错（`n%10; n/=10` 就是对的），
需要推断程序员意图。

### 3. 算法复杂度 / 超时

```c
for (int i = 1; i <= n; i++)
    printf("%d\n", sum(i));   // sum 内部又循环 i 次 → O(n²)
```

**样本：stu_04、stu_10**

为什么不查：需要跨函数分析循环嵌套深度。很多场景循环里调函数
是必要的，误报风险高。

### 4. 运行时越界（下标来自输入）

```c
scanf("%d", &d);
b[0] = d;
b[i] = a[b[i-1]];      // 下标取决于运行时输入
```

**样本：stu_09**

为什么不查：`d`、`a[]` 的值只有运行时才知道，静态无法判断范围。

## 五、已知的误报风险点

这些地方 csub 可能会报错，如果你遇到了请记下来。

| 场景 | 风险 | 当前处理 |
|---|---|---|
| scanf 传数组名 | 曾误报成漏 `&` | **已修**（stu_11） |
| `n/2` 递归除法 | 曾误报"改成浮点" | 已豁免（stu_02） |
| 函数片段（无 main） | 曾报 ERROR 挡住诊断 | 改成 W17 提示（stu_02） |
| 全大写未声明标识符 | 不报（当成头文件宏） | 有意取舍，见下 |
| 结构体省略成员类型 | 曾崩溃 | 已修（stu_04） |

### 那条有意取舍

`_is_likely_external_macro()` 把全大写标识符一律当成「来自被忽略
头文件的宏」而容忍。依据：`real_fortranobject.c`（1400 行 numpy C 扩展）
里 `NPY_INTP_FMT` 这类宏出现十几次，不放宽就是十几条假错误。

代价：全大写拼写错误查不出来。**这个取舍值得，不是 bug。**

## 六、csub vs gcc

| 维度 | gcc | csub |
|---|---|---|
| 语法错误 | ✅ 完整 | ⚠️ 子集（会漏，不会误报） |
| 类型检查 | ✅ 完整 | ⚠️ 简化模型 |
| 未初始化 | 需 -Wall | ✅ 默认开 |
| 数组越界（常量） | ✅ 需 -Warray-bounds | ✅ 默认开 |
| 数组越界（循环变量） | ❌ 一般不报 | ✅ W16（有限场景） |
| 整数溢出 | ✅ -Woverflow | ✅ W14 |
| 死循环 | ❌ | ✅ W15/W18 |
| 栈溢出风险 | ❌ | ✅ W19 |
| 内存泄漏 | ❌（需 -fanalyzer） | ❌ |
| 算法复杂度 | ❌ | ❌ |
| 中文诊断 | ❌ | ✅ |

**结论**：csub 和 gcc 的重合度已经很高，真正的差异在
「能编译但会出事」这一层——W13/W15/W16/W18/W19 这几条是 gcc 不做的。

## 七、如果你要用它

```bash
python csub.py check  你的文件.c     # 找错
python csub.py report 你的文件.c     # 带源码上下文
```

**预期管理**：

- 它的诊断是**建议**，不是判决。看提示，自己想清楚对不对。
- **如果它报了一个你认为正确的代码，那是它的 bug**，
  请记下来（放 `examples/student_real/` 或直接告诉我）。
- 它查不出算法错误，别指望它告诉你"这个思路不对"。

## 八、这份文档怎么来的

11 份样本全部来自真实学生（BUPT 课程作业、PTA/LeetCode 提交）。

每份都做了三件事：
1. 跑 csub，记录诊断
2. 跑 `gcc -fsyntax-only -Wall -Wextra`，对照
3. 人工判断每条诊断是真检出还是误报

**没有一份是我编的。** 这是它和 `examples/err_*.c`（AI 构造用例）
的根本区别——后者反映的是"AI 认为学生会犯什么错"，
前者反映的是"学生真的犯了什么错"。

实测下来，两者的差异很大：

- 我以为学生常犯 off-by-one、忘写 `&`
- 实际最常见的是**指针语义混淆**（`char*` 存字符串数组、`*b[j]` 多解一层）
- 以及**算法/性能问题**（超时、栈溢出），占了一半以上
