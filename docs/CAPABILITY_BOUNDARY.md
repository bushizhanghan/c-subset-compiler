# csub 能力边界

> 这份文档回答一个问题：**csub 能查什么，不能查什么，什么情况下会误报。**
>
> 依据是 **22 份真实学生代码**的实测（`examples/student_real/`），
> 其中 **11 份带老师批改标注**，共 60 条人工确认的错误。
>
> 不是自评，是跑出来的。

---

## 一、先说结论

| 维度 | 现状 |
|---|---|
| 诊断规则 | **39 条**（13 错误 + 26 警告） |
| 真实学生代码崩溃 | **0**（22 份全部跑通） |
| 真实学生代码误报 | **0** |
| 老师标注的错误能查 | **12 / 60 = 20%** |
| 明确的能力盲区 | 5 类，见第四节 |

**两个最重要的数字：**

- **20%** —— 老师批改的 60 条真实错误里，csub 只能查出 12 条。这是这条技术路线的真实上限。
- **0 误报** —— 22 份学生代码 + 4 份开源代码（2500+ 行）零假阳性。这比检出率更重要。

## 二、能查什么（按可信度排序）

### 高可信 — 几乎不会误报

| 码 | 查什么 | 验证来源 |
|---|---|---|
| E1 | 使用未声明变量 | 多份 |
| E2 | 使用未初始化变量 | stu_01 |
| E3 | 重复声明 | — |
| E4/E14 | 函数参数个数不对（含可变参数） | stu_20 |
| E5 | 调用未声明函数 | — |
| E11 | break/continue 只能用在循环内部 | — |
| E12 | 除数是常量 0 | — |
| E13 | 常量下标越界 | — |
| E15 | 结构体没有该成员 | — |
| E17 | 表达式嵌套过深（健壮性保护） | fuzz |
| E18 | 给数组整体赋值 | — |
| W6 | 变量声明后从未使用 | — |
| W19 | 局部大数组爆栈（>256KB） | **stu_09** |
| W28 | 参数声明了但从未使用 | stu_20 |

### 中可信 — 有明确豁免规则，边界清楚

| 码 | 查什么 | 豁免条件 |
|---|---|---|
| E16 | scanf 漏写 `&` | **数组名/指针变量不报**（stu_11 撞出的误报） |
| W2 | 有符号/无符号混合比较 | 常量、指针比较不报；`strlen` 按 size_t（stu_05） |
| W3 | 整数除法丢精度 | **分子是变量时不报**（`n/2` 是惯用法，stu_02） |
| W5 | `if (a = 1)` 赋值当比较 | — |
| W8 | 非 void 函数缺 return | if 链有无 else 兜底；有 return 就放行 |
| W9 | 返回局部变量地址 | 全局/static/形参/malloc 不报 |
| W11 | 指针与整数隐式转换 | 空指针常量、显式转换不报 |
| W13 | `if (cond);` 空分支 | **条件含函数调用不报**（`while(getchar())`） |
| W23 | 格式串与参数类型不匹配 | 只查字面量格式串；未知 typedef 不报（stu_12/01/05） |
| W24 | 无效果表达式语句 | 有副作用的都放行；宏名放行（stu_13） |
| W25 | 调标准库函数但漏 include | 有非标准头（可能是预编译头）不报（stu_16） |
| W26 | 指针参数收到非指针值 | 空指针常量、未知 typedef 不报（stu_01） |
| W27 | return 类型与函数声明不匹配 | 未知 typedef 不报；只查指针性（stu_17） |
| W29 | malloc 分配不足却用变量下标 | 只查常量字节数、元素数 ≤1（stu_22） |

### 低可信 — 只在形状非常明确时才报

| 码 | 查什么 | 限制 |
|---|---|---|
| W10 | 数组传给非数组形参 | 只看直接传数组名 |
| W12 | char 赋超范围值 | 只看字面量常量 |
| W14 | 常量表达式溢出 int | **long/unsigned 一律不报**（回绕是定义行为） |
| W15 | 循环死循环 | 只在「变量 vs 常量」比较中收集；有 break/return/函数调用不报 |
| W16 | 循环下标越界（off-by-one） | 只支持 for 标准形态 + 常量边界 |
| W18 | 递归到不了基线 | 只认 `n ± 常量` 直接形态 |
| W20 | 块作用域逃逸 | 只查 `&裸变量名`，不查 `&a[i]` / `&s.member` |
| W21 | 读未初始化数组元素 | 全局数组、有任一元素写过、scanf 填充都不报 |
| W22 | 复合赋值右侧又写同一变量 | 指针目标、含函数调用不报 |
| W4 | float 赋给 int | — |

## 四、明确查不出来的（能力盲区）

这五类**不是 bug，是结构上做不到**。

### 1. 算法/数学逻辑错误

```c
// 完美数：只加小因子，漏了配对的 num/i
if (num % i == 0) { ans += i; }     // 该同时加 num/i
```

**样本：stu_19（2 条）、stu_18（5 条）、stu_15（5 条）、stu_20（6 条）**

为什么不查：语法、类型、控制流全部正确。错误在于"没理解数学事实"
（因子成对出现）或"算法结构不对"（三数之和该固定一个数再双指针）。

### 2. 内存泄漏 / 资源泄漏

```c
int* ans = malloc(n * sizeof(int));
if (k == 0) { return; }        // 提前返回，ans 没 free
free(ans);
```

**样本：stu_06**

为什么不查：需要路径分析 + 别名分析。真实代码里提前 return
到处都是，误报风险远超收益。

### 3. 跨行语义不一致

```c
while (x != 0) {
    int y = x % m;      // 按 m 进制取位
    x /= 10;            // 却按 10 进制右移
}
```

**样本：stu_07**

为什么不查：每一行单独都合法，错误在于两行之间的**意图不一致**。
同样的代码形状有对有错（`n%10; n/=10` 就是对的）。

### 4. 运行时越界（下标/长度来自输入或参数）

```c
bool f(int* nums, int numsSize) {
    if (numsSize < 3) { if (nums[1] > nums[0]) ... }   // numsSize==1 时越界
}
```

**样本：stu_15、stu_18**

为什么不查：`nums` 是 `int*` 参数，长度完全未知；
`numsSize < 3` 是运行时条件。静态推不出。

### 5. 算法复杂度

```c
for (i = 1; i <= n; i++) printf("%d", sum(i));   // sum 内部又循环 i 次
```

**样本：stu_04、stu_10、stu_16**

为什么不查：需要跨函数分析循环嵌套深度。很多场景循环里调函数
是必要的，误报风险高。

## 五、已知的误报风险点

这些地方 csub 曾经报错过，修完但值得记下来。

| 场景 | 曾经的错误 | 现状 |
|---|---|---|
| scanf 传数组名 | 误报成漏 `&` | 已修（stu_11） |
| `n/2` 递归除法 | 误报"改成浮点" | 已豁免（stu_02） |
| 函数片段无 main | 报 ERROR 挡住诊断 | W17 已整个删除 |
| 多字符常量 `'ans'` | 判成"字符常量未闭合" | 已修（stu_21） |
| 空定义宏 | 展开成 `0` 伪造出常量语句 | 已修（stu_13） |
| 未知 typedef（npy_int/LinkList） | 格式串/指针检查误报 | 已豁免 |
| 可变参数 `...` | 被当成参数名 | 已修（stu_20） |
| 可变参数函数调用 | E4 要求参数个数严格相等 | 已修（stu_20） |

### 那条有意取舍

`_is_likely_external_macro()` 把全大写/含连续大写段的标识符
当成「来自被忽略头文件的宏」而容忍。依据：
`real_fortranobject.c`（1400 行 numpy C 扩展）里 `NPY_INTP_FMT`、
`Py_RETURN_NONE` 这类宏出现十几次，不放宽就是十几条假错误。

代价：全大写拼写错误查不出来。**这个取舍值得，不是 bug。**

## 六、csub vs gcc

| 维度 | gcc | csub |
|---|---|---|
| 语法错误 | ✅ 完整 + 错误恢复 | ⚠️ 子集，单层恢复 |
| 类型检查 | ✅ 完整 | ⚠️ 简化模型 |
| 未初始化 | 需 -Wall | ✅ 默认开 |
| 数组越界（常量） | ✅ 需 -Warray-bounds | ✅ 默认开 |
| 数组越界（循环变量） | ❌ | ✅ W16（有限场景） |
| 整数溢出 | ✅ -Woverflow | ✅ W14 |
| 死循环 | ❌ | ✅ W15/W18 |
| 栈溢出风险 | ❌ | ✅ W19 |
| malloc 分配不足 | ❌ | ✅ W29 |
| 漏 include | ✅ error | ✅ W25 |
| 内存泄漏 | ❌（需 -fanalyzer） | ❌ |
| 算法复杂度 | ❌ | ❌ |
| 中文诊断 | ❌ | ✅ |

**结论**：csub 和 gcc 的重合度已经很高，真正的差异在
「能编译但会出事」这一层——W13/W15/W16/W18/W19/W29 是 gcc 不做的。

## 七、如果你要用它

```bash
python csub.py check  你的文件.c     # 找错
python csub.py report 你的文件.c     # 带源码上下文
```

**预期管理**：

- 它的诊断是**建议**，不是判决。看提示，自己想清楚对不对。
- **如果它报了一个你认为正确的代码，那是它的 bug**，
  请记下来（放 `examples/student_real/` 或直接告诉我）。
- 它查不出算法错误，别指望它告诉你"这个思路不对"。
- **20% 是老师标注错误的检出率**，别期待更多。

## 八、这份文档怎么来的

22 份样本全部来自真实学生（BUPT 课程作业、PTA/LeetCode 提交），
其中 11 份带老师的人工批改标注。

每份都做了三件事：
1. 跑 csub，记录诊断
2. 跑 `gcc -fsyntax-only -Wall -Wextra`，对照
3. 人工判断每条诊断是真检出还是误报

**没有一份是编的。** 这是它和 `examples/err_*.c`（AI 构造用例）
的根本区别——后者反映的是"AI 认为学生会犯什么错"，
前者反映的是"学生真的犯了什么错"。

实测下来，两者的差异很大：

- 我以为学生常犯 off-by-one、忘写 `&`
- 实际最常见的是**指针/类型混淆**、**输入流程错误**、**算法逻辑错误**
- 而且**算法/数学逻辑错误占了 60 条标注里的绝大部分**

### 一个反复验证的规律

**能查到的 12 条，全是「形式能核对」的：**

| 类型 | 规则 |
|---|---|
| 类型不匹配 | W11 / W27 |
| 未初始化/未声明 | E1 / E2 |
| 指针参数给值 | W26 |
| 格式串不匹配 | W23 |
| 漏 include | W25 |
| 无效果表达式 | W24 |
| malloc 大小不足 | W29 |

**查不到的 48 条，全是「需要理解意图」的：**

初值选择、赋值顺序、分支互斥、边界返回、漏吃换行、
运算符笔误（`q=q%j`）、复杂度、内存泄漏、运行时边界。

**这个分界很硬**：形式层能核对的，基本都做了；
语义层要推断意图的，一条也做不了。
